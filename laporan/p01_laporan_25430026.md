\## C. Analisis Wajib



\### 1. Titik Analisis 1–4

\* \*\*Titik Analisis 1 (Konfigurasi User \& Akses):\*\* Pembedaan user `mhs\_026` dan `dev\_026` bertujuan untuk menerapkan \*Principle of Least Privilege\* (akses minimal). User `dev\_026` hanya diberikan hak akses pada database proyek `klinik\_026`.

\* \*\*Titik Analisis 2 (Pengujian Hak Akses):\*\* Pengujian akses membuktikan bahwa privileges berjalan dengan benar, di mana `dev\_026` tidak diperbolehkan membaca atau memodifikasi database lain seperti `kopma\_026`.

\* \*\*Titik Analisis 3 (Autentikasi Mode Cookie):\*\* Pengubahan mode `auth\_type` menjadi `cookie` di phpMyAdmin memaksa setiap pengguna untuk memasukkan username dan password manual, sehingga mencegah akses otomatis tanpa otorisasi.

\* \*\*Titik Analisis 4 (Manajemen Repositori Git):\*\* Penggunaan `.gitignore` penting untuk memastikan file kredensial atau konfigurasi sensitif tidak ikut terunggah ke repositori publik.



\### 2. Perbedaan Kode Galat 1044, 1045, dan 1142

\* \*\*Galat 1044 (Access Denied for Database):\*\* Terjadi ketika user berhasil login, tetapi mencoba mengakses atau memanipulasi database yang tidak berada dalam daftar wewenangnya (misal: `dev\_026` menjalankan `USE kopma\_026;`).

\* \*\*Galat 1045 (Access Denied / Invalid Credentials):\*\* Terjadi di tingkat autentikasi awal akibat username salah, password salah, atau asal koneksi host tidak sesuai saat mencoba login ke MySQL/MariaDB.

\* \*\*Galat 1142 (Command/Table Access Denied):\*\* Terjadi ketika user memiliki akses ke database tertentu, tetapi tidak memiliki izin (\*privilege\*) khusus untuk menjalankan perintah tertentu (seperti `SELECT`, `INSERT`, atau `DROP`) pada tabel tertentu di dalam database tersebut.
