## 2. Ringkasan Dasar Teori
MariaDB merupakan sistem manajemen basis data relasional (RDBMS) yang mengelola data dalam bentuk tabel terstruktur. Dalam pengelolaannya, keamanan dan hak akses diatur melalui perintah *Data Control Language* (DCL) seperti `GRANT` dan `REVOKE`. MariaDB mendukung enkapsulasi hak akses berdasarkan host dan database tertentu untuk menjaga isolasi data. Penggunaan `utf8mb4` direkomendasikan sebagai standar pengkodean karakter universal. Selain itu, integrasi alur kerja pengembangan dilakukan dengan mengolaborasikan perintah eksekusi skrip SQL berbasis CLI dan manajer kontrol versi Git/GitHub.

5. **Inisialisasi Database dan Hak Akses User**  
   Mengeksekusi perintah pembuatan database `klinik_026` dan `kopma_026` serta alokasi hak akses untuk akun `dev_026`, `kaylani_25430026`, dan `tamu_026`:
   ```sql
   -- 1. Mengamankan Akun Root
   CREATE USER IF NOT EXISTS 'root'@'localhost' IDENTIFIED BY '<password_root>';

   -- 2. Membuat Database
   CREATE DATABASE IF NOT EXISTS klinik_026 CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE DATABASE IF NOT EXISTS kopma_026 CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

   -- 3. Membuat Akun / User
   CREATE USER IF NOT EXISTS 'dev_026'@'localhost' IDENTIFIED BY '<password_dev>';
   CREATE USER IF NOT EXISTS 'kaylani_25430026'@'localhost' IDENTIFIED BY '<password_kaylani>';
   CREATE USER IF NOT EXISTS 'tamu_026'@'localhost' IDENTIFIED BY '<password_tamu>';

   -- 4. Mengatur Hak Akses (Privileges)
   GRANT ALL PRIVILEGES ON klinik_026.* TO 'dev_026'@'localhost';
   GRANT ALL PRIVILEGES ON kopma_123.* TO 'kaylani_25430026'@'localhost';
   GRANT ALL PRIVILEGES ON kopma_026.* TO 'kaylani_25430026'@'localhost';
   GRANT SELECT ON kopma_026.* TO 'tamu_026'@'localhost';

   -- 5. Menerapkan Perubahan Privileges
   FLUSH PRIVILEGES;
   ```

**Titik Analisis 1–4:** Pengaturan hak akses menentukan tingkat visibilitas objek database yang dapat diakses oleh suatu user.

### Tabel Analisis Kode Galat

| Kode Galat | Nama Galat | Penyebab Utama | Solusi Penanganan |
| :--- | :--- | :--- | :--- |
| `ERROR 1045 (28000)` | Access denied for user | Username/password salah saat otentikasi login. | Periksa kembali ketersediaan user dan kecocokan password. |
| `ERROR 1044 (42000)` | Access denied to database | User berhasil masuk, tapi tidak punya izin ke DB tertentu. | Berikan hak akses database via perintah `GRANT`. |
| `ERROR 1142 (42000)` | Command denied for table | User tidak punya hak akses eksekusi DDL/DML pada tabel. | Berikan hak akses operasi spesifik pada tabel tersebut. |
